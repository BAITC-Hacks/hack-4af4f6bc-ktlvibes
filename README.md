# AI Sana — каталог практических бизнес-задач

MVP для хакатона: бизнес описывает задачу, уточняет карточку и подтверждает публикацию. Команды видят общий каталог, сами отправляют предложения, а бизнес вручную выбирает или отклоняет отклики. После подтверждения фактического прогресса команда получает баллы.

## Запуск

Нужен Docker с Compose. Из корня репозитория:

```sh
docker compose up --build
```

Откройте `http://localhost:5173`. API доступен на `http://localhost:8000`, проверка состояния — `http://localhost:8000/api/health`. При первом запуске API создаёт таблицы и загружает демо-данные: пять опубликованных задач, пять черновиков, пять команд и пять откликов. Повторный запуск не дублирует их. База хранится в Docker volume `postgres_data`.

Для входа в готовые демо-аккаунты используйте `demo-business-1@example.local` (бизнес) или `demo-team-6@example.local` (команда) и пароль из `DEMO_USER_PASSWORD` (по умолчанию `demo12345`). Другие аккаунты можно создать на странице регистрации. После входа роли и доступ определяются сессией, а не выбором профиля в интерфейсе. Для HTTPS задайте `COOKIE_SECURE=true`.
Пароль демо-аккаунтов назначается при их создании или миграции. Позднее его можно изменить в «Мой профиль»; изменение переменной окружения не меняет уже сохранённые пароли.

Для отдельного запуска фронтенда поднимите `db` и `api` через Compose, затем:

```sh
cd web
npm ci
npm run dev
```

Vite направляет запросы `/api` на `http://localhost:8000`. Если API работает по другому адресу, задайте `VITE_API_PROXY_TARGET` **до** запуска Vite. В Compose этот адрес уже установлен как `http://api:8000`, поскольку `localhost` внутри контейнера указывает на сам контейнер `web`.

## Устройство MVP

- `web/` — React, TypeScript, Vite; вход, регистрация, свой профиль, страницы бизнеса, каталог и карточка с откликами.
- `api/` — FastAPI, SQLModel; проверка роли по серверной сессии, вопросы, рейтинг, задачи, предложения и прогресс.
- `db/` — инициализация PostgreSQL; `e2e/` — браузерный сценарий конструктора задачи.

Фронтенд обращается к API через относительные пути `/api/...`; Vite проксирует их к бэкенду. Вход выдаёт HTTP-only cookie с серверной сессией. Бизнес управляет только своими задачами и их откликами, команда видит опубликованные задачи и собственные отклики.

## Пользователи

Бизнесы и команды хранятся в таблице `users` с ролями `business` и `team`. ID пользователя используется для задач и откликов. При первом запуске создаются пять пользователей каждой роли. Если база уже содержит старые таблицы `business` и `team`, API переносит их записи и связи в `users`; старые таблицы остаются в базе для восстановления данных.

API пользователей: `POST /api/users` для регистрации, `GET /api/users/{id}`, `PATCH /api/users/{id}` и `DELETE /api/users/{id}` для своего аккаунта. Регистрация требует `role`, `name`, `email` и `password`; для команды можно также указать `interests`, `skills` и `technologies`. `POST /api/auth/login`, `GET /api/auth/me` и `POST /api/auth/logout` управляют входом. `points` начисляются через подтверждение прогресса. Роль нельзя изменить, а аккаунт нельзя удалить, если за ним уже есть задачи или отклики; API вернёт `409`.

## Рейтинг и каталог

Рейтинг от 0 до 100 рассчитывает сервер по осмысленно заполненным полям подтверждённой карточки:

| Сведения | Баллы |
| --- | ---: |
| Контекст и потребность | 10 + 10 |
| Данные и способ доступа | 10 + 10 |
| Ожидаемый результат | 15 |
| Метрика и целевое значение успеха | 10 + 5 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт и формат взаимодействия | 5 + 5 |

Уровни: 0–39 — «черновик», 40–69 — «рабочая», 70–89 — «готовая», 90–100 — «приоритетная». Уровень «черновик» относится к рейтингу **опубликованной** задачи: она остаётся в каталоге, и команда может откликнуться. Неподтверждённый черновик задачи в каталоге не показывается.

Каталог содержит все опубликованные задачи, сортирует их по убыванию рейтинга и позволяет фильтровать по теме и уровню. При равном рейтинге выше стоит более поздняя публикация. Во время уточнения предварительный рейтинг сохраняется вместе с ответами в черновике. В каталоге новая оценка появляется после ручного подтверждения карточки бизнесом.

## Вопросы и AI

Сервис анализирует заполненные поля и подбирает уточняющие вопросы. Интерфейс показывает их по одному: после каждого ответа сохраняет черновик, пересчитывает рейтинг и запрашивает следующий вопрос с учётом новых сведений. Кнопка «Сохранить и выйти» сохраняет также текущий введённый ответ; продолжить можно из кабинета бизнеса.

Если заданы `AI_API_KEY` и `AI_API_URL`, сервис отправляет исходное описание и текущую карточку в совместимый с Chat Completions API; модель задаётся `AI_MODEL`. Ожидаемый ответ — JSON с одним следующим вопросом: `{"questions":[{"field":"users","text":"..."}]}`. Схема ответа проверяется сервером; вопросы по уже содержательным полям исключаются. При отсутствии API или ошибке ответа используются локальные вопросы в последовательности от контекста к критериям успеха. Под полем ответа показан образец конкретного ответа. Сервис не дописывает факты в карточку: ответы вводит и подтверждает бизнес.

Баллы за поле начисляются, когда ответ содержит конкретные сведения. Пустые отписки, общие фразы и повтор уже учтённого ответа не повышают рейтинг; для целевого значения нужно число или явное проверяемое условие. Эта локальная проверка основана на правилах, поэтому бизнес может уточнить ответ вручную.

## Демонстрация за 5 минут

1. Войдите как **Демо бизнес**, откройте «Кабинет бизнеса» → «Создать задачу». Введите слабое описание и тему, создайте черновик.
2. Ответьте на первый вопрос и посмотрите, как изменился рейтинг. Нажмите «Сохранить и выйти», снова откройте черновик в кабинете и продолжите вопросы. Укажите название и тему, затем подтвердите публикацию.
3. Откройте каталог и опубликованную карточку. Выйдите и войдите как команда, например **Data Lab**; отправьте идею, план, срок и HTTP(S)-ссылку на прототип.
4. Выйдите и снова войдите как владелец задачи. В карточке вручную выберите или отклоните отклик. Для выбранной команды опишите выполненный этап и подтвердите прогресс: ей начислится 10 баллов. Обновите страницу, чтобы увидеть сохранённое решение.

Для короткой проверки только пути «каталог → отклик → решение» можно взять готовую задачу **«Сократить ожидание ответа»**, принадлежащую «Демо бизнес». Низкий рейтинг не блокирует отклик: это видно на задачах уровня «черновик» в каталоге.

Сборка фронтенда: `cd web && npm run build`. Браузерный тест конструктора описан в [e2e/README.md](e2e/README.md).
